Además de representar enteros, puede interpretarse una secuencia de bits como un número que tiene parte entera y fraccionaria. Para explicarlo se escribe un **punto binario** como separador didáctico de posiciones: a la izquierda se usan potencias no negativas de 2 y a la derecha potencias negativas. El punto puede ser **implícito** en el formato de almacenamiento.

La primera posición fraccionaria pesa `2⁻¹ = 0,5`; la segunda `2⁻² = 0,25`; la tercera `2⁻³ = 0,125`; siguen `1/16`, `1/32`, `1/64`, etc.

```text
1001.100101₂
= 1×2³ + 0×2² + 0×2¹ + 1×2⁰
  + 1×2⁻¹ + 0×2⁻² + 0×2⁻³ + 1×2⁻⁴ + 0×2⁻⁵ + 1×2⁻⁶
= 9 + 0,5 + 0,0625 + 0,015625
= 9,578125₁₀
```

En una representación didáctica puede emplearse el punto `.` para mostrar visualmente el límite entre ambas partes, pero es importante distinguir **notación visible** y **bits realmente almacenados**. El punto no ocupa un bit por sí mismo.

### 17.1. Decimal fraccionario a binario: multiplicaciones sucesivas

1. Separar parte entera y parte fraccionaria del número decimal.
2. Convertir la parte entera con divisiones sucesivas.
3. Multiplicar la parte fraccionaria por 2.
4. Anotar la parte entera obtenida (`0` o `1`) como el siguiente bit fraccionario.
5. Volver a multiplicar solo la nueva parte fraccionaria; repetir hasta obtener 0 o hasta alcanzar la precisión elegida.
6. Unir los bits obtenidos en el **mismo orden de las multiplicaciones**.

Ejemplo exacto: `0,375₁₀`.

| Fracción anterior | Multiplicación   | Bit obtenido | Nueva fracción |
| ----------------: | ---------------- | -----------: | -------------: |
|             0,375 | 0,375 × 2 = 0,75 |            0 |           0,75 |
|              0,75 | 0,75 × 2 = 1,5   |            1 |            0,5 |
|               0,5 | 0,5 × 2 = 1,0    |            1 |              0 |

Resultado: `0,375₁₀ = 0.011₂`, pues `1/4 + 1/8 = 0,375`.

Ejemplo periódico: `0,2₁₀`.

```text
0,2 × 2 = 0,4  → bit 0
0,4 × 2 = 0,8  → bit 0
0,8 × 2 = 1,6  → bit 1; queda 0,6
0,6 × 2 = 1,2  → bit 1; queda 0,2
... se repite el estado inicial
```

Su expansión binaria es `0.0011001100110011…₂` y **no termina**. **Precisión:** Eso no significa que 0,2 sea irracional: sigue siendo el racional `1/5`. Lo que ocurre es que su representación posicional en base 2 es **periódica** y no tiene longitud finita. Una aproximación truncada comete un error que depende de los bits fraccionarios disponibles.
